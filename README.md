# めだか台帳（仮称）仕様書一式

改良メダカの飼育者が「どの容器に、どの系統の何世代目が何匹いて、いつ採卵し、いつ孵化し、どう選別し、いくらで売ったか」を記録するiOSアプリの仕様書です。
Claude Codeに渡して実装を始めるための文書として書いています。

## 文書の構成

| ファイル | 内容 | 読む人 |
|---|---|---|
| `CLAUDE.md` | Claude Code向けのプロジェクト規約（技術方針、命名、進め方、禁止事項） | Claude Code |
| `docs/PRD.md` | 製品要件。誰の何を解決するか、機能範囲、Free/Pro、成功指標、リスク | 企画者、Claude Code |
| `docs/DOMAIN.md` | 改良メダカの繁殖と販売の用語と流れ。モデル設計の根拠 | Claude Code、レビュー協力者 |
| `docs/ARCHITECTURE.md` | 技術スタック、SwiftDataのデータモデル、計算ロジック、エクスポート形式 | Claude Code |
| `docs/SCREENS.md` | 画面ごとの構成、遷移、状態、操作 | Claude Code、デザイン |
| `docs/ROADMAP.md` | 6週間の日割り計画とマイルストーン | 企画者、Claude Code |
| `docs/LAUNCH.md` | 名称、価格、ストア掲載、テスター募集、法務と税務の確認事項 | 企画者 |
| `docs/DECISIONS.md` | 仕様レビューへの回答。他の文書と食い違う場合はこちらが優先 | Claude Code |

## 前提

- 対象はiPhone（iOS 18以上）。Apple純正フレームワークのみで構築する。
- サーバーを持たない。データは端末内に保存し、バックアップはファイル書き出しで行う。
- 収益はApp内課金の買い切りPro一本。広告は出さない。
- 開発はClaude Codeで行う。企画と仕様はこの文書群で管理し、実装中に判断に迷った点はコードで決めずに報告してもらう。

## 開発の進め方

- Macを使わずに進める。開発はクラウドのClaude Code、確認はスマホのGitHubアプリ（PRに貼られるスクリーンショット）とTestFlight。
- `.xcodeproj` はXcodeGenで生成するため、Xcodeで手作りしない。

## Claude Codeへの最初の指示（コピーして使う）

```
このリポジトリの CLAUDE.md と docs/ 配下の仕様書をすべて読んでから作業を始めてください。
実装するのは docs/ROADMAP.md の第1週の範囲だけです。
仕様に書かれていない判断が必要になった箇所は、自分で決めずに「要確認」として一覧にして報告してください。
第1週の完了条件を満たしたら、動作確認の手順と一緒に報告して止まってください。
```

## 更新の決まり

- 仕様の変更は該当する文書を直してから実装する。コードだけ先に変えない。
- 用語は `docs/DOMAIN.md` の定義を正とする。画面の文言もここに合わせる。
- 価格、アプリ名、Bundle IDなど未確定の値は `docs/LAUNCH.md` の「未確定事項」にまとめ、確定したら各文書に反映する。
