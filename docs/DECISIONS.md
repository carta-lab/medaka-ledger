## B. 第1週の範囲（1-1）

第1週の受け入れ確認は、F1、F2、F3のうち次を対象外とする。各機能の週で確認する。

- 写真（容器、系統、群）：第3週
- 最終水換えからの日数：第2週（第1週のカードでは表示しない）
- 系統詳細の「血統図」「写真」「販売」タブ：第3週、第4週
- F3の出来事の削除は第1週（11/5）に含める

系統詳細は「群」タブだけを第1週（11/4）に作る。入手個体の群の登録をここから呼ぶため。

## C. 群と匹数

- **匹数の未入力（1-3）**：`Cohort.count` を `Int?` にする。`nil` は「未計数」、`0` は「0匹」。
- **負数（1-4）**：匹数が分かっている群で、結果が負になる操作（現在数を超える分割、増減、販売）は保存前に止め、「現在の匹数（n匹）を超えています。数え直す場合は計数修正を使ってください」と出す。`nil` の群は検査しない（分割しても元は `nil` のまま）。
- **出来事の削除（2：11/5）**：削除できるのは各群の最新の出来事だけ。分割と統合は、相手側の対応する出来事も相手の最新である場合に限り、両方まとめて削除する。条件を満たさないときは「後の記録があるため削除できません。計数修正か移動で直してください」と出す。
- **出来事に持たせる値**：`CohortEvent` に `previousCount: Int?`、`previousStageRaw: String`、`previousStatusRaw: String` を足し、削除時はこれで元に戻す。
- **日付**：出来事の日付は表示と並び順のためだけに使う。過去の日付で入れても、状態（容器、匹数）は保存した時点で反映する。
- **作成の記録**：`CohortEventKind` に `created` を足し、群を作ったときに必ず1件残す。タイムラインの最初の行になる。
- **分割で引き継ぐ項目**：系統、世代、孵化日、入手日、段階、`originBatch`、`isSample`。雌雄の内訳は引き継がない。分割先の容器は必須。
- **統合の条件**：同じ系統、同じ世代、かつ同じ親魚セットから生まれた群どうし（または両方とも入手個体）に限る。容器は違ってよい。吸収する側の容器と段階を残し、孵化日は早いほうを残す。条件を満たさなければ統合ボタンを無効にし、理由を出す。
- **状態の変化**：匹数が0になっても自動では変えない。0になった時点で「この群を終了しますか（完売、全滅、そのまま）」を出す。容器の「今いる群」は `status == active` の群。
- **親魚セットに使われた群**：削除できない。メニューに「アーカイブ」を出す（`status = archived`）。
- **日齢**：孵化日を0日目とする。入手個体は「入手から○日」を出す。
- **交配の子の世代（第2週）**：雄と雌の系統が違う場合、子は新しい系統のF1（`generation = 1`）。同じ系統なら `max(雄の世代, 雌の世代) + 1`。

## D. 容器と系統

- **削除（1-5）**：容器と系統に削除はない。アーカイブだけ。
- **アーカイブの条件**：稼働中の群がいる容器はアーカイブできない。「先に群を移動してください」と出す。系統は稼働中の群がいてもアーカイブできるが、確認を出す。
- **写真（1-2）**：容器も複数枚付けられる。Freeの上限は1対象3枚（F9、PRD 7章に合わせる）。
- **グリッドの分け方**：`location` の文字列（前後の空白を除いて完全一致）でセクションを分ける。空は「場所未設定」として最後に置く。屋外か室内かはカードのアイコンで示す。
- **連続登録の名前**：末尾の数字を1増やし、桁数は元の桁数を下限にゼロ埋めを保つ（A-9→A-10、A-09→A-10、B-007→B-008）。末尾に数字がなければ「-2」を付ける。
- **並べ替え（3-5）**：グリッド上のドラッグは作らない。メニューの「並べ替え」でリスト表示に切り替え、`onMove` でセクション内だけ並べ替える。セクションをまたぐ移動は、容器の編集で置き場所を変える。アクセシビリティ用の大きな文字サイズではグリッドを1列にする。
- **系統一覧の並び（3-4）**：手動の並び順だけにする。あいうえお順はMVPで提供しない。
- **表現タグの候補**：ラメ、黒ラメ、体外光、三色、紅白、錦、朱赤、黄、白、黒、琥珀、オーロラ、サファイア、ブラックリム、透明鱗、ヒカリ体型、ダルマ、半ダルマ、ロングフィン。自由入力したタグは、全系統のタグの和集合として次回から候補に出す。
- **品種名の補完**：アーカイブ済みの系統も含め、重複を除いて出す。
- **入手個体の群の容器**：任意。未設定は「容器未設定」と表示する。

## E. ホームとサンプルデータ

- **産卵期外のホーム（1-6）**：PRD F8に合わせる。見出しの直後に「水温の記録」ボタンと「越冬中の群」を置き、孵化予定と育卵中の枠は畳む。
- **越冬中の群**：産卵期外に、屋外の容器にいる稼働中の群。
- **最近の記録**：第1週は群の出来事だけを出す。採卵、孵化、選別、販売、水換えは、それぞれの機能を作る週に加える。種類ごとに最新5件を取得し、アプリ内で日付順に混ぜる（3-6）。
- **タップ数（1-8）**：PRD 4章の「2タップ」は「ホームのクイック操作から、選択1回と保存1回」と読む。採卵と水換えはこれを満たす。写真と増減は対象外。
- **サンプルデータ（1-7）**：全モデルに `isSample: Bool = false` を足す。サンプルは `isSample = true` で作り、Freeの上限の数え方から除外する。「サンプルを全削除」は `isSample == true` を全モデルから消す。
- **サンプルの作り方**：JSONファイルではなく、コードで生成する `SampleDataSeeder`（`Domain/`）にする。第1週はデバッグメニューから、第5週からオンボーディングと設定から呼ぶ。

## F. 第2週以降（先に決めておくもの）

- **孵化予定日の水温（1-9）**：ARCH 4.1の順に統一する。その日の容器の水温記録、なければロットの水温、なければ既定水温。
- **子の系統を決める時期（1-10）**：同じ系統どうしの親魚セットは作成時に子の系統を親の系統に決める。交配の親魚セットは子の系統を空のまま作り、最初の孵化記録で決める（新しい系統の作成か既存の選択）。交配の系統は孵化するまで系統一覧に現れず、Freeの上限にも数えない。
- **血統の循環（1-11）**：循環の判定は、いまたどっている経路の上だけで行う。雄側と雌側に同じ群が出てもよい。
- **水換え警告（1-12）**：設定値は産卵期用と産卵期外用の2つ（ARCH 3.3）。
- **産卵期の通知（1-13）**：産卵期の最初の月の前月15日の朝8時。
- **DOMAINの確認依頼（1-14）**：ROADMAPの「着手前の検証」で行う。
- **経費（1-15）**：手数料と送料だけを扱う。それ以外の経費は扱わない（I）。
- **選別の回数（1-16）**：`round` は1、2、3、その他は0。
- **出品文のサイズ（1-17）**：`Cohort` に `sizeText: String = ""`（例「1.5〜2cm」）を足す。
- **販売のスナップショット（1-18）**：`Sale.strainName` を `breedNameSnapshot` と `lineNameSnapshot` に分ける。
- **CSVの期間（1-19）**：書き出し時だけ開始日と終了日を指定できる。台帳画面の切り替えは3つのまま。
- **成功指標の判定日（1-20）**：2027年7月1日。
- **群CSV**：Freeでも書き出せる。販売CSVはPro。
- **販売で減らす匹数**：匹は数量、ペアは2×数量、トリオは3×数量。稚魚まとめは減らす匹数を入力させる。卵は減らさない。
- **軽量版バックアップ**：写真を含まないバックアップは「追記」でだけ読み込める。
- **代表写真**：`Photo` に `isCover: Bool = false` を足す。全画面表示から「代表にする」で設定し、未設定なら最も古い写真を使う。

## G. 技術的な難所への対応

- **3-1**：A表の並行処理の決定で解消する。
- **3-2 ModelActorがメインで動く問題**：`ModelActor` は `Task.detached` の中で生成して使う。重い処理の後で、実機で画面が固まらないことを確認する。
- **3-3 `@Query` の決まり**：CLAUDE.mdの決まりに例外を設ける。集計（最終水換え日、系統ごとの件数と匹数、品種名の重複除去、選別の累計、売上集計）と、関係をまたぐ検索（容器名と系統名）は、述語で絞れるところまで絞って取得し、`Domain/` の関数でアプリ内で計算してよい。集計用の値をモデルに重複して持たせることはしない（性能の目安を満たさなかった場合に再検討する）。
- **3-7 カメラ**：`UIImagePickerController` を `UIViewControllerRepresentable` で包む。撮影日はImageIOでEXIFの撮影日時を読み、無ければ保存時刻を使う。
- **3-8 バックアップの形式**：フォルダ形式（パッケージ）をやめ、Apple Archive（`AppleArchive` フレームワーク、LZFSE圧縮）で1ファイルにまとめた `名前.medakabackup` にする。中身の構成（`manifest.json` と `photos/`）は変えない。外部ライブラリなしで書き出しと展開ができ、メールやクラウド経由でも壊れない。
- **3-9 通知の出し直し**：起動時、フォアグラウンド復帰時、採卵ロット、水温記録、設定値の変更時に、孵化予定の通知を全て消して予定日の近い順に最大50件を予約し直す。
- **3-10 Proの表示**：起動直後は「確認中」の状態を持ち、Pro限定の表示（年別集計、CSV、出品文）は確認が済むまで出さない。Freeの上限による保存の停止は、確認が済んでから判定する。

## H. Claude Codeの判断（v1.1の再レビュー、2026-10-22、要確認）

「自律的に進めてください」の指示を受けて、Claude Codeが決めた事項。
のりさんが違う判断をした場合は、この節を直してから実装を直す。

- **CIを回す条件**：privateリポジトリではmacOSランナーの実行時間が10倍で数えられるため、A表の「PRとpushごと」を「PRへのpushと手動実行」に絞る。mainへのpushとdocsだけの変更では回さない。同じPRで新しいpushがあれば古い実行は取り消す。
- **出来事の「最新」**：保存した順で決める。`CohortEvent` に `createdAt: Date`（保存日時）を足す。タイムラインの並びは `date`（新しい順）、同じ日付なら `createdAt`（新しい順）。
- **状態の変更の値**：`CohortEvent` に `statusRaw: String`（変更後の状態）を足す。`statusChange` のときだけ入れる。統合で吸収された側の `merge` にも `merged` を入れる。
- **未計数の群（`count == nil`）**：統合はどちらかが未計数なら結果も未計数。増減（死亡、飛び出し、譲渡、その他）は匹数を未計数のまま、出来事だけ残す。計数修正は未計数からでも数を入れられる。
- **App Groupが使えないとき**：シミュレータとDebugビルドでは、App Groupのコンテナが取れなければアプリ内の Application Support に保存する。Releaseビルドでは保存せずにエラー画面を出す。CIは署名なしでビルドするため、この切り替えで動く。
- **分割で作る群**：分割先の群には `created` を残さず、`split`（+n）を最初の出来事にする。分割の取り消しで分割先の群は消える（分割先の最新の出来事が `split` のとき、つまり後の記録が無いときだけ取り消せる）。`sizeText` は引き継ぎ、ラベルは空にする。
- **雌雄の内訳**：分割、統合、増減で自動では変えない。群の編集で直す。
- **統合の取り消し**：匹数、段階、状態は元に戻すが、統合で早いほうに変えた孵化日は戻さない。
- **移動の取り消し**：移動元の容器がアーカイブ済みなら取り消さず、「移動元の容器がアーカイブされています」と出す。
- **終了や統合の取り消し**：取り消すと飼育中に戻る群の容器がアーカイブ済みなら取り消さず、「この群の容器がアーカイブされています」と出す。統合は両方の群を確かめてから戻す。
- **作成の記録の匹数**：`created` の `countDelta` に作成時の匹数を入れ、匹数が分かっているときは `reasonRaw` を `recount` にする。0匹と未計数を見分けるため（属性は増やさない）。
- **終了した群**：状態が飼育中でない群（完売、統合済み、全滅、アーカイブ）は、操作ボタンを全て無効にする。出来事の削除は使える（終了の取り消しに使う）。
- **群の削除**：群を削除しても、分割や統合の相手の群は変えない。相手のタイムラインには「削除済みの群」と出す。
- **アーカイブの解除**：容器と系統は、アーカイブ済みの一覧から開いた詳細で「アーカイブを解除」できる（誤操作を戻せるようにするため）。
- **容器一覧のセクションの順**：各セクションの先頭の容器の並び順で決め、「場所未設定」は最後。
- **デバッグメニュー**：Debugビルドだけ、ホームの右上に置く。サンプルの投入、サンプルの全削除、全データの削除。
- **サンプルデータv0**：楊貴妃と幹之の2系統。容器6個（屋外の棚A、B、室内ラック）、群4つ（入手2つと、分割で作った2つ）。全て `isSample = true`。
- **表示文字列**：`Localizable.xcstrings` は `scripts/gen-xcstrings.py` でソースから生成する（XcodeのないLinuxで作業するため）。文言に埋め込む値は文字列にしてから渡す（キーの書式を `%@` にそろえるため）。
- **第1週に作らないもの**：繁殖タブと販売タブは「次の更新で使えます」の空状態だけ。ホームのクイック操作4つは枠だけで、押せない。設定画面は第4週。

### 第2週（2026-10-22、要確認）

- **設定画面の前倒し**：完了条件「設定を20℃に変えると13日後」を確かめるため、設定画面の「計算」（積算温度、既定の水温、水換えの警告日数、産卵期の月）だけを第2週に作る。ホーム右上の歯車から開く。バックアップ、サンプル、Pro、用語の説明は第4週以降。
- **孵化予定日が出ないとき**：水温が0℃以下の日だけが365日続く設定（積算温度に届かない）では予定日を出さず、「孵化予定日を計算できません」と表示する。通知も出さない。
- **水換えの警告**：飼育中の群がいる容器で、最終水換えの記録があるものだけ警告する。記録の無い容器は「水換えの記録なし」と表示するだけで、警告もホームの期限超えにも入れない（登録したばかりの容器が並んで警告になるのを避けるため）。
- **孵化記録**：孵化したロットにもう一度孵化を記録できる。2回目以降は、このロットから生まれた飼育中の群に足すか、新しい群にするかを選ぶ。足すときは匹数を `adjust` で足し、メモに「孵化」と入れる。廃棄したロットには記録できない。
- **子の系統**：同系統の親魚セットは作成時に親の系統に決める。交配は最初の孵化記録で、新しい系統（初期値は「雄の品種×雌の品種」）か既存の系統を選ぶ。決めた後の孵化は同じ系統になる。
- **親魚セットの終了**：「今日で終了」だけ（終了日を選ぶ画面は作らない）。終了後は採卵を記録できない。
- **採卵ロットの廃棄**：育卵中のロットを左にスワイプして廃棄できる。廃棄すると通知も止まる。
- **通知**：孵化予定日の朝8時と産卵期の最初の月の前月15日の朝8時。許可は最初の採卵ロットを保存したときに、理由を一行で示してから求める。許可が無い間は予約しない。予約は、起動時、フォアグラウンド復帰時、採卵、孵化、廃棄、作業記録の保存、設定を閉じたときに全て消して作り直す。
