# PRD：めだか台帳（仮称）

版：v1.0（2026-10-22）
対象：iPhone、iOS 18以上
用語は `DOMAIN.md` に従う。

## 1. 一文で言うと

改良メダカを増やして売る人のための、容器、系統、世代、採卵、選別、販売を一つにつなげた台帳アプリ。

## 2. 背景

改良メダカは飼育ペットとして犬猫に次ぐ3位に入り、副業として飼育と販売を行う人が増えている。
品種は500から600種に増え、1匹1万5千円の個体も流通する。
ファン層は60から70代中心から30代にも広がり、SNSで系統の写真を発信する人が多い。

それなのに、App Storeにあるメダカ関連のアプリは育成ゲームと汎用の水槽管理ログだけで、系統と世代と容器を結び付けて記録できる台帳は見当たらない（2026年10月時点の調査）。
飼育者は手帳、ホワイトボード、表計算で記録しているか、記録を諦めている。

個人開発のアプリとして狙う理由は三つある。
記録の構造が「生き物を増やして売る」趣味に固有で、汎用アプリでは代替できないこと。
利用者が飼育と販売にすでにお金を使っていて、買い切り千円前後の抵抗が小さいこと。
サーバー不要で作れるため、運用費がかからず小遣い稼ぎの収支が成り立つこと。

## 3. 対象利用者

### 主対象：副業ブリーダー

- 容器20から100個を屋外に並べ、系統5から20本を累代している。
- 産卵期は毎朝の採卵と針子の世話に追われ、記録は後回しになる。
- ヤフオクとイベントで年に数万円から数十万円を売り、確定申告の要否が気になり始めている。
- スマホはiPhone。手が濡れたまま片手で操作することが多い。
- 困りごと：どの容器の群が何世代目か分からなくなる。採卵した卵がいつ孵るか毎回計算している。選別の結果を残していないので翌年に活かせない。売上を紙のメモで集計している。

### 副対象：趣味上級者

- 容器5から20個。系統2から5本。
- 売るより増やすこと自体が楽しみで、系統図と写真が残ることに価値を感じる。
- Free枠で使い始め、容器や系統が増えた時点でProに移る。

### 対象外

- 専門店や業者。在庫数千匹、スタッフ複数、PC運用が前提で、要件が別物になる。
- 水質管理が主目的の熱帯魚や海水魚の飼育者。既存の水槽管理アプリが向く。

## 4. 製品の方針

- **群単位で記録する**。個体を一匹ずつ登録させない。親魚候補は匹数の少ない群として扱う。
- **オフラインで完結する**。アカウント登録もサーバーもない。データは端末に保存し、バックアップはファイル書き出しで行う。
- **屋外で片手で使える**。採卵と水換えは、ホームのクイック操作から選択1回と保存1回で記録できる。ボタンは大きく、文字はDynamic Typeに追従する。
- **季節に合わせる**。産卵期のホームは採卵と孵化を前面に、越冬期は水温と生存確認を前面に出す。
- **データを人質にしない**。Free利用者でもJSONの完全バックアップとその読み込みはできる。Proで開くのは分析と出力の機能に限る。
- **用語は飼育者の言葉を使う**。針子、弾く、累代、親魚セットのように、現場の言い方をそのまま画面に出す。

## 5. 機能要件（MVP）

各機能に受け入れ条件を付ける。
条件を満たさない機能はリリースに含めない。

### F1 容器台帳

容器を名前、種類、容量、置き場所（屋外か室内か、棚や列）で登録し、並べ替えられる。
容器一覧は置き場所ごとのグリッドで、各容器に今いる群（系統名、世代、匹数）と最終水換えからの日数を表示する。

受け入れ条件：
- 容器を30個登録しても一覧の表示が1秒以内。
- 容器をアーカイブできる。アーカイブ済みは一覧から消え、過去の記録からはたどれる。
- 容器に写真を付けられる（F9。Freeは3枚まで）。
- 容器は削除せずアーカイブだけにする。稼働中の群がいる容器はアーカイブできない。

### F2 系統台帳

系統を品種名、系統名（呼び名）、入手元、入手日、表現タグ、メモ、代表写真で登録する。
系統詳細には、世代ごとの群、血統図、写真、販売の累計を表示する。

受け入れ条件：
- 表現タグは候補（ラメ、体外光、三色、紅白、ブラックリム、オーロラ、透明鱗、ヒレ長、ダルマ、サファイアなど）から選び、自由入力も加えられる。
- 品種名の入力時に、登録済みの品種名から補完できる。

### F3 群の管理

群は系統、世代、匹数、容器、成長段階（針子、稚魚、若魚、成魚）、孵化日、メモ、写真を持つ。
群に対して次の操作ができる。

- 移動：容器を変える。
- 分割：匹数を指定して新しい群に分け、別の容器へ移す。
- 統合：同じ系統と世代の群を一つにまとめる。
- 増減：死亡、飛び出し、譲渡、計数修正を理由付きで記録する。
- 成長段階の更新。

受け入れ条件：
- すべての操作が群の時系列（タイムライン）に残り、誤った記録は出来事の削除で匹数と容器が元に戻る。
- 匹数は概数として扱い、未入力（未計数）と0匹を区別する。匹数が分かっている群で、結果が負になる操作は止める。
- 出来事の削除は各群の最新の出来事に限る（詳細は `DECISIONS.md` C）。
- 群詳細に孵化からの日数を表示する。

### F4 親魚セットと採卵ロット

親魚セットは雄の群、雌の群（同じ群でもよい）、雄雌の匹数、容器、開始日、終了日を持つ。
採卵ロットは親魚セット、採卵日、卵数（概数）、育卵容器または容器名、水温、状態（育卵中、孵化、廃棄）を持ち、孵化予定日を計算して表示する。

孵化予定日は積算温度で求める。
設定の積算温度（初期値250℃日）を、入力した水温（未入力なら設定の既定水温）で割った日数を採卵日に加える。
日ごとの水温は、その日の容器の水温記録、なければロットの水温、なければ既定水温の順に使う（`ARCHITECTURE.md` 4.1）。

受け入れ条件：
- ホームのクイック操作「採卵」から、親魚セットの選択と保存で記録できる。
- 孵化を記録すると、新しい群が作られ、針子の容器を指定できる。同じ系統どうしなら世代は `max(雄, 雌) + 1`、系統は親と同じ。
- 雄と雌の系統が異なる場合、最初の孵化記録で子の系統を決める。初期値は「雄の品種×雌の品種」の新しい系統で、既存の系統も選べる。子の世代はF1。
- 採卵ロットの一覧で孵化予定日までの残り日数を表示し、予定日を過ぎたロットを目立たせる。
- 孵化予定日の朝にローカル通知を出す。通知の許可は最初の採卵ロットを保存したときに求める。

### F5 選別記録

群に対して選別を記録する。
回数（1回目、2回目、3回目）、日付、基準（体型、色、ラメ、体外光、ヒレ、その他）、残し数、弾き数、弾きの行き先（餌用、格安販売、別容器、処分）、メモ、写真を持つ。

受け入れ条件：
- 弾きの行き先に「別容器」を選ぶと、弾いた分を新しい群として分割できる。
- 系統詳細に、世代ごとの残し数と弾き数の合計を表示する。

### F6 販売台帳

販売を日付、対象の群（任意）、単位（匹、ペア、トリオ、卵、稚魚まとめ）、数量、単価、合計、販路（ヤフオク、自店、イベント、委託、直接、その他）、手数料、送料、発送日、購入者メモ、状態（出品中、売約、発送済、取消）、メモで記録する。
月別の売上、手数料、送料、純額を集計する。

受け入れ条件：
- 群を指定して販売を記録すると、群の匹数を減らすか確認する。
- 月別集計と年別集計を表示する。
- Proで、開始日と終了日を指定してCSVを書き出せる。列は `ARCHITECTURE.md` の定義に従う。

### F7 作業記録

容器に対して水換え（割合）、足し水、掃除、薬浴、水温、その他を日付と共に記録する。
容器一覧と容器詳細に最終水換えからの日数を表示し、設定の日数（産卵期は初期値14日、産卵期外は初期値45日）を超えた容器を目立たせる。

受け入れ条件：
- ホームのクイック操作「水換え」から、容器の選択と保存で記録できる。
- 水温の記録は採卵ロットの孵化予定日の計算に反映される。

### F8 ホーム

今日やることと状態を一画面に出す。

- 孵化予定が今日か明日の採卵ロット。
- 育卵中のロットの残り日数。
- 水換えの期限を超えた容器。
- 出品中の販売。
- クイック操作：採卵、水換え、写真、増減。

受け入れ条件：
- 起動から1秒以内に表示される。
- 産卵期（設定の月、初期値4月から9月）以外は、孵化と採卵の枠を畳んで水温と生存確認を上に出す。

### F9 写真

群、容器、系統、選別に写真を複数枚付けられる。
撮影日を保存し、系統詳細で世代順に並べて見られる。

受け入れ条件：
- 保存時に長辺1600ピクセルへ縮小し、1枚あたり500KB以下を目安にする。
- 写真はアプリ内に保存し、端末の写真ライブラリには書き込まない（利用者が書き出したときだけ書き込む）。

### F10 血統図

群から親魚セットをたどり、雄側と雌側の祖先を世代ごとに木で表示する。

受け入れ条件：
- Freeでは2世代、Proでは無制限にさかのぼる。
- 各ノードに系統名、世代、孵化日、代表写真を表示し、タップで群詳細へ移動する。

### F11 出品文テンプレ（Pro）

群を選ぶと、品種名、系統、世代、匹数と雌雄、サイズ、孵化時期、親の表現、飼育環境、死着保証、注意事項の定型文を組み立ててコピーできる。
文面の雛形は設定で編集できる。

受け入れ条件：
- 端末内の情報だけで生成する。通信しない。
- 雌雄の匹数が未入力なら、その行を省く。

### F12 バックアップと書き出し

JSON形式の完全バックアップを書き出し、読み込める。
CSVは群一覧と販売台帳を書き出せる。

受け入れ条件：
- JSONの書き出しと読み込み、群CSVはFreeでも使える。販売CSVはPro。
- 読み込みは「置き換え」と「追記」を選べ、置き換えの前に確認を出す。
- 書き出しにはスキーマのバージョン番号を含め、将来の読み込みで変換できるようにする。

### F13 Pro課金

StoreKit 2の買い切り（非消耗型）でProを解放する。
復元に対応する。

受け入れ条件：
- 購入前にFreeの制限とProの内容を一覧で示す。
- 購入が失敗しても入力中のデータを失わない。
- 返金や復元の状態を起動時に再確認する。

### F14 設定、オンボーディング、サンプルデータ

設定：積算温度、既定水温、水換え警告日数（産卵期、産卵期外）、産卵期の月、出品文の雛形、バックアップ、Pro、プライバシーポリシー、用語の簡単な説明。
初回起動では、容器を3個と系統を1本作る短い案内を出し、サンプルデータの読み込みも選べる。

受け入れ条件：
- サンプルデータは1タップで全削除できる。サンプルはFreeの上限に数えない。
- 設定値の変更は孵化予定日の計算に即時反映される。

## 6. MVPに含めないもの

- iCloud同期（複数端末）。データモデルはCloudKitに移行できる制約で作っておき、第2段階で有効化する。
- ホーム画面ウィジェット（孵化カウントダウン、水換え期限）。
- Apple Intelligenceによる出品文の言い換え。iOS 26以上の対応端末に限られるため後回し。
- 相場や価格のメモ、手数料と送料以外の経費（餌、容器、仕入れ）の記録。第2段階で扱う。
- iPad最適化、英語化。文字列はString Catalogに置き、後から足せるようにする。
- 個体識別、表現の自動判定、飼育者同士の交流。

## 7. FreeとPro

| 項目 | Free | Pro（買い切り） |
|---|---|---|
| 容器 | 6個まで | 無制限 |
| 系統 | 2本まで | 無制限 |
| 稼働中の親魚セット | 2つまで | 無制限 |
| 群、採卵、選別、作業記録 | 無制限 | 無制限 |
| 写真 | 1対象あたり3枚 | 無制限 |
| 血統図 | 2世代 | 無制限 |
| 販売台帳 | 記録と月別集計 | 年別集計、CSV書き出し |
| 出品文テンプレ | なし | あり |
| JSONバックアップ | あり | あり |

価格は1,200円を仮置きし、`LAUNCH.md` の未確定事項で確定する。
Freeの上限は「趣味で始めた人が最初の春を越えられる量」を基準に決めた。
容器6個と系統2本は、親魚セット1つから採卵し、針子容器と育成容器を回すのに足りる。
副業規模（容器20個以上）になると必ず上限に当たる。

## 8. 成功指標

産卵期の山（4月から6月）が終わった2027年7月1日に判定する。

- Proの購入が累計100本。
- App Storeの「メダカ」検索で5位以内（4月から6月）。
- 初回起動から7日後に再起動した利用者が35%以上。
- TestFlightのブリーダー5人のうち3人以上が、公開後も手帳や表計算から乗り換えて使い続けている。

指標の計測はApp Store Connectの数値と、TestFlight参加者への聞き取りで行う。
アプリ内に計測SDKは入れない。

## 9. リスクと対策

- **作り手が飼育者でない**：用語や運用の誤りが信頼を落とす。対策として、着手前の検証（`ROADMAP.md`）でブリーダー2人に `DOMAIN.md` を読んでもらい、TestFlightで5人に使ってもらう。募集はXのメダカ界隈で行う。
- **春以外は使われない**：越冬期は記録が止まり、解約ではなく放置になる。買い切りなので収益への影響は小さいが、翌春に戻ってもらうため、産卵期の最初の月の前月15日に「親魚セットを組みましょう」の通知を1回だけ出す。
- **データ消失への不安**：端末内保存のため、機種変更や故障で消える。JSONバックアップを初回起動時と定期的に案内し、第2段階でiCloud同期を入れる。
- **写真で容量が膨らむ**：縮小保存と、容器や群のアーカイブ時に写真を残すか選べる仕組みで抑える。
- **名称の衝突**：アプリ名の重複と商標を公開前に確認する。
- **審査**：買い切りと復元だけの単純な課金にし、Freeの機能が単体で成立するようにして審査の指摘を避ける。

## 10. 法務、プライバシー、倫理

- 魚類の販売に動物取扱業の登録は不要であり、アプリは許認可を扱わない。
- 購入者メモは利用者の端末内にだけ保存される。アプリは外部に送信しない。プライバシーポリシーにその旨を書く。
- 弾いた個体の行き先に放流は用意しない。
- 確定申告の要否は利用者の責任であり、アプリは税額を計算しない。販売台帳のCSVは申告の元資料として使える形式にする。
- 個人の開発者アカウントで公開するため、App Storeには開発者の本名が表示される。
